Section 2

2. From Train Map to Adjacency Matrix

We already know how to draw our train network as a graph:

  • Each station is a node.
  • Each train is a directed edge from its start station to its end station.

Humans like pictures, but computers love tables. Instead of drawing arrows, we can store the same information in a matrix:

  • Rows = “from” stations
  • Columns = “to” stations
  • Entry (i, j) tells us whether we can go directly from station i to station j.

This table is called an adjacency matrix. For our 6 stations (KOL, NAG, DEL, PUN, SEC, KAN) we’ll have a 6×6 matrix. The diagonal cells (KOL→KOL, NAG→NAG, …) don’t really make sense as journeys, so we’ll mark them as “—”.

In the simplest version, each off-diagonal cell is:

  • 0 → no direct train from i to j
  • 1 → at least one direct train from i to j

Later, we’ll make the entries more interesting (train numbers, distances, times). But first, let’s build the basic 0/1 matrix for our mini train world.

Section 3

3. Direct, One-Hop, Two-Hop… and “Reachable or Not?”

Our 0/1 matrix answers a yes/no question:

“Can I go from station A to station B in one direct train?”

But life (and train travel) is rarely that simple. Often we are okay with changing trains:

  • 0 hops → A to B in one train (direct).
  • 1 hop → A → C → B (change once at C).
  • 2 hops → A → C → D → B (change twice), and so on.

In graph language:

  • A path is a sequence of edges you can follow.
  • The length of the path is the number of edges you use.

With our adjacency matrix, we can ask:

  • “Is there a path from A to B of length 2?” (one hop)
  • “Length 3?”
  • “Length ≤ k?”

If we allow any number of hops, the question becomes:

“Is B reachable from A at all?”

Taking all possible hops into account and marking all reachable pairs in a big matrix is called taking the transitive closure of the graph.

Within one hop matrix (≤1 hop)

Key concept: checking ≤1 hop

To check if A can reach B in at most one hop:

  1. Look at row A in the direct matrix. Find all stations C where direct[A][C] = 1.
  2. For each such C, look at row C. If direct[C][B] = 1, then A → C → B is a valid one-hop route.
  3. Also remember: if direct[A][B] = 1, we already have a 0-hop route.


Example: Can we go from SEC to DEL in at most one hop?

  • Direct matrix: direct[SEC][DEL] = 0 → no direct train.
  • But direct[SEC][PUN] = 1 (T4) and direct[PUN][DEL] = 1 (T5).
  • So SEC → PUN → DEL is a one-hop route. Therefore withinOne[SEC][DEL] = 1.

Section 4

4. Flipping the Story: Graph of Trains + Delay as “Water in Pipes”

So far, we treated stations as nodes and trains as edges. But we can flip the viewpoint:

  • Nodes = trains (T1, T2, …, T9)
  • Edge between two trains if there is a station where you can get off one and catch the other.

The label on the edge is the transfer station (and we could also store timing info).

Example:

  • T1 (KOL→NAG) and T3 (NAG→SEC) share station NAG. If T1 arrives at NAG before T3 departs, you can connect there. So we draw an edge between T1 and T3 labelled “NAG”.

A path in this new graph is a sequence of trains you can take one after another: T1 → T3 → T4 → T5 is a journey KOL → NAG → SEC → PUN → DEL.

This “train graph” is great for two things:

  1. Planning connections: can I eventually reach some train I really want to catch?
  2. Tracking delay propagation: if one train is late, which other trains get delayed because they are behind it on shared tracks?

Section 5

5. Turning the Train Story into Pseudocode

Now we move from pictures and tables to pseudocode. Our goal: given all the train cards, build:

  • A dictionary of trains
  • A list of stations
  • An adjacency matrix for direct routes
  • Matrices that tell us which stations are reachable in ≤ 1 hop, ≤ 2 hops, …, ≤ n hops.

This is pure computational thinking:

  • choose representations,
  • break problems into steps,
  • write clear procedures.

5.1 – Data structures

Representation 
* `trains` : dictionary
  * key: train id like `"T1"`
  * value: record with fields:
    * `start` (station name)
    * `end`   (station name)
    * `distance` (in km)

* `stations` : dictionary used as a set
  * key: station name
  * value: `true` (we don’t care about the value, only the keys)

* `stationIndex` : dictionary
  * key: station name
  * value: index from `0` to `n-1`

* `direct` : `n × n` matrix of 0/1
  * `direct[i][j] = 1` if there is a train whose start station has index `i` and end station has index `j`.

5.2 – Building the direct matrix

Procedure `buildDirectMatrix(trains)` 
1. Create empty dictionary `stations = {}`.
2. For each train `t` in `trains`:
   * Let `s = trains[t].start`, `e = trains[t].end`.
   * Add `s` to `stations`.
   * Add `e` to `stations`.
3. Let `n = number of keys in stations`.
4. Create `n × n` matrix `direct` filled with 0.
5. Create empty dictionary `stationIndex`.
6. Let `i = 0`.
7. For each station `name` in `stations` (in any fixed order):
   * `stationIndex[name] = i`
   * `i = i + 1`
8. For each train `t` in `trains`:
   * `i = stationIndex[ trains[t].start ]`
   * `j = stationIndex[ trains[t].end ]`
   * Set `direct[i][j] = 1`.
9. Return `direct` and `stationIndex`.

📖 Code-by-Code Analysis

Step 1: Create empty dictionary `stations = {}`

What it does: Creates an empty dictionary to track all unique stations.

Why: We need to discover all stations before we can build a matrix. We use a dictionary because it automatically handles duplicates (each station name appears only once as a key).

Example: stations = {} starts empty, ready to collect station names.

Step 2: For each train, collect start and end stations

What it does: Loops through every train in our dataset and extracts the start and end station names.

Why: We need to know ALL stations before building our matrix. By adding both start and end stations to our dictionary, we ensure no station is missed.

Example: If train T1 goes Mumbai→Pune, we add both "Mumbai" and "Pune" to stations.

Step 3: Let `n = number of keys in stations`

What it does: Counts how many unique stations we found.

Why: This tells us the size of our matrix. If we have 5 stations, we need a 5×5 matrix.

Example: If stations = {"Mumbai": true, "Pune": true, "Delhi": true}, then n = 3.

Step 4: Create `n × n` matrix `direct` filled with 0

What it does: Creates a square matrix (same number of rows and columns) with all values set to 0.

Why: We start with "no connections" (all 0s) and will add connections (change to 1) as we process the trains. This is the adjacency matrix foundation.

Example: For 3 stations: [[0,0,0], [0,0,0], [0,0,0]]

Steps 5-7: Map station names to matrix indices

What it does: Assigns each station a number from 0 to n-1. This creates a mapping from station names (like "Mumbai") to row/column indices (like 0).

Why: Matrices use numbers for indexing, not strings. We need to convert "Mumbai" → 0, "Pune" → 1, etc.

Example: stationIndex = {"Mumbai": 0, "Pune": 1, "Delhi": 2}

Step 8: Mark direct connections in the matrix

What it does: For each train, find the row index of its start station and column index of its end station, then set that cell to 1.

Why: This encodes "there is a direct train from station i to station j" as direct[i][j] = 1.

Example: If train goes Mumbai(0) → Pune(1), we set direct[0][1] = 1.

Step 9: Return the results

What it does: Sends back both the adjacency matrix and the station-to-index mapping.

Why: We need both! The matrix shows connections, but we also need stationIndex to know which row/column represents which station.

Result: Now we can ask "Is there a train from Mumbai to Delhi?" by checking direct[stationIndex["Mumbai"]][stationIndex["Delhi"]].

5.3 – Within-one-hop matrix

Procedure `withinOneHop(direct)` 
Input: `direct` = `n × n` 0/1 matrix
Output: `withinOne` = `n × n` 0/1 matrix

1. Let `n` be the number of rows in `direct`.
2. Create `withinOne` as an `n × n` matrix of 0s.
3. For each `i` from `0` to `n-1`:
   For each `j` from `0` to `n-1`:
   * If `direct[i][j] == 1`, then set `withinOne[i][j] = 1`
   * Else:
     * For each `k` from `0` to `n-1`:
       * If `direct[i][k] == 1` AND `direct[k][j] == 1`,
         then set `withinOne[i][j] = 1` and break out of the `k` loop.

📖 Code-by-Code Analysis

Step 1: Get matrix size

What it does: Reads the number of rows (stations) from the input matrix.

Why: We need to know how many stations we're working with to build our output matrix of the same size.

Step 2: Create result matrix

What it does: Creates a new n×n matrix filled with 0s.

Why: This will hold our result. We start assuming no connections and will mark reachable pairs as 1.

Step 3a: Loop through all station pairs (i, j)

What it does: For every possible pair of stations (from station i to station j), we check if j is reachable from i.

Why: We need to examine every possible journey to build the complete reachability matrix.

Step 3b: Check for direct connection

What it does: If direct[i][j] == 1, copy that to withinOne[i][j] = 1.

Why: Direct connections (0 hops) are also reachable within 1 hop. We preserve all direct routes.

Example: If there's a direct train Mumbai→Delhi, that connection stays in our result.

Step 3c: Search for one-hop paths (the magic!)

What it does: If no direct connection exists, try to find an intermediate station k where:
• There's a train from i to k (direct[i][k] == 1)
• AND there's a train from k to j (direct[k][j] == 1)

Why: This finds one-hop paths (i → k → j). If we can reach j from i by changing trains once, j is reachable within one hop.

Example: No direct Mumbai→Bangalore, but there's Mumbai→Pune and Pune→Bangalore. So we set withinOne[Mumbai][Bangalore] = 1.

Optimization: We break as soon as we find one path because we only care if it's reachable (yes/no), not how many paths exist.

🎯 Big Picture: What does this achieve?

Result: The withinOne matrix tells us which stations are reachable with at most 1 train change.

Includes:
• Direct connections (0 hops)
• One-transfer journeys (1 hop)

Use case: "Show me all cities I can reach from Mumbai with at most one train change" → Look at row Mumbai in withinOne.

5.4 – Two-hop & “one-more-hop”

Procedure `withinTwoHops(direct, withinOne)` 
1. Let `n` be the number of rows.
2. Copy `withinOne` into `withinTwo`.
3. For each `i` from `0` to `n-1`:
   For each `j` from `0` to `n-1`:
   * If `withinTwo[i][j] == 1`, continue.
   * Else, for each `k` from `0` to `n-1`:
     * If `withinOne[i][k] == 1` AND `direct[k][j] == 1`,
       then set `withinTwo[i][j] = 1` and break.
General Procedure `oneMoreHop(direct, nHop)` 
1. Let `n` be the number of rows.
2. Copy `nHop` into `nPlusOne`.
3. For each `i` from `0` to `n-1`:
   For each `j` from `0` to `n-1`:
   * If `nPlusOne[i][j] == 1`, continue.
   * Else, for each `k` from `0` to `n-1`:
     * If `nHop[i][k] == 1` AND `direct[k][j] == 1`,
       then set `nPlusOne[i][j] = 1` and break.
4. Return `nPlusOne`.

📖 Code-by-Code Analysis

Step 1: Get matrix size

What it does: Reads the number of stations from the input matrix.

Why: We need this to create the result matrix of the correct size.

Step 2: Copy `nHop` into `nPlusOne`

What it does: Creates a new matrix by copying all existing reachability from nHop.

Why: We want to add new reachable connections without losing the old ones. If station j was reachable in n hops, it's definitely reachable in n+1 hops too!

Think of it like: "Keep all the cities we could reach before, and now let's find additional cities by taking one more train."

Step 3a: Loop through all station pairs

What it does: Examines every possible journey from station i to station j.

Why: We need to check all pairs to build the complete reachability picture.

Step 3b: Skip if already reachable

What it does: If nPlusOne[i][j] == 1, skip to the next pair.

Why: Performance optimization! If we already know j is reachable from i (from the copied matrix), there's no need to search for more paths.

Analogy: "If I already have a route to Bangalore, I don't need to search for another one."

Step 3c: Search for "one more hop" paths 🔥

What it does: For each intermediate station k, check if:
• We can reach k from i in n hops: nHop[i][k] == 1
• AND there's a direct train from k to j: direct[k][j] == 1

Why: This is the algorithm's heart! We're asking: "Can I reach j from i by going to some intermediate city k (in n hops), then taking one direct train from k to j?" If yes, j is reachable in n+1 hops.

Example:
• Mumbai → Delhi is possible in 2 hops
• Delhi → Bangalore has a direct train
• Therefore: Mumbai → Bangalore is possible in 3 hops (2 + 1)

Key insight: We're building on previous results (nHop) and extending them by one more direct connection.

Step 4: Return the result

What it does: Returns the updated reachability matrix.

Result: nPlusOne[i][j] = 1 means "station j is reachable from station i in at most n+1 hops".

🎯 The Power of Iteration

This is the magic: By calling oneMoreHop repeatedly, we can find all reachable stations:

  • Start: direct (0 hops = direct trains only)
  • Call 1: oneMoreHop(direct, direct) → ≤1 hop
  • Call 2: oneMoreHop(direct, oneHop) → ≤2 hops
  • Call 3: oneMoreHop(direct, twoHop) → ≤3 hops
  • ... keep going until no new connections are found

Real-world use: "Which cities can I reach from Mumbai with at most 3 train changes?" → Call oneMoreHop three times!

💡 Pro tip: This algorithm is essentially computing the transitive closure of a graph - finding all indirect connections by repeatedly extending paths.

Starting from direct (0 hops), we can call oneMoreHop repeatedly:

  • after 1 call → paths of length ≤ 1
  • after 2 calls → paths of length ≤ 2
  • …
  • after (n−1) calls → all possible simple paths.

This repeated “one more hop” process is the algorithmic way to build the transitive closure.

6. Adding Labels: Train Numbers, Distances & Shortest Paths

A plain adjacency matrix only stores 0 or 1. But we can attach more information to each edge:

  • Which train(s) connect two stations
  • Distances in km
  • Travel times

When we store extra data on edges, we get an edge-labelled graph.

Example ideas:

  • directTrains[i][j] could be a list of train ids that go from station i to station j.
  • directDist[i][j] could be the shortest distance among all those trains (0 if no direct train).

Because KOL and DEL have two different trains (T6 and T7) with different distances and times, directTrains[KOL][DEL] = [T6, T7] and directDist[KOL][DEL] = 1450 (we keep the shorter distance).

By combining these edge labels with our “one more hop” idea, we can find shortest total distance paths between any two stations.

6.1 – Building a distance matrix

Procedure `buildDirectDistance(trains)` 
1. Use the same `stations` and `stationIndex` construction as in `buildDirectMatrix`.
2. Let `n` be the number of stations.
3. Create `directDist` as an `n × n` matrix filled with 0.
4. For each train `t` in `trains`:
   * `i = stationIndex[ trains[t].start ]`
   * `j = stationIndex[ trains[t].end ]`
   * `d = trains[t].distance`
   * If `directDist[i][j] == 0` (no distance yet), set `directDist[i][j] = d`.
   * Else set `directDist[i][j] = min(directDist[i][j], d)`.
5. Return `directDist`.

For each pair of stations (i, j), directDist[i][j] stores the shortest known direct distance among all trains that go from i to j. If directDist[i][j] = 0, we treat that as “no direct train”.

6.2 – Distances with one hop

Procedure `withinOneHopDistance(directDist)` 
1. Let `n` be the number of stations.
2. Create `oneHopDist` as an `n × n` matrix.
3. For all `i, j`, set `oneHopDist[i][j] = directDist[i][j]`.
4. For each `i` in `0..n-1`:
   For each `j` in `0..n-1`:
   * For each `k` in `0..n-1`:
     * If `directDist[i][k] > 0` AND `directDist[k][j] > 0` then:
       * `newDist = directDist[i][k] + directDist[k][j]`
       * If `oneHopDist[i][j] == 0` OR `newDist < oneHopDist[i][j]` then
         set `oneHopDist[i][j] = newDist`.
5. Return `oneHopDist`.

This is the distance version of our one-hop matrix: for each possible intermediate station k, we check if going i → k → j gives a shorter route than what we already know.
