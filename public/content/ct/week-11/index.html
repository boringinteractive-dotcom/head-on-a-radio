2. DFS on the Train Network (Stations as Nodes)

We explore the mini train world as a directed graph, then watch DFS run step-by-step with a live call stack and visited set.

We already know our train world as a directed graph:

  • Each station is a node.
  • Each train is a directed edge from its start station to its end station.

Suppose we start at Kolkata (KOL) and we want to explore:

“Which stations are reachable if I keep following trains as long as I can?”

There are two natural strategies:

  • Breadth-first search (BFS):
    First visit all neighbours of KOL, then all stations at distance 2, then distance 3, and so on.
  • Depth-first search (DFS):
    From KOL, pick one neighbour, go there, then from there pick a neighbour, and keep going deeper and deeper until you get stuck.
    Only then come back and try other choices.

In DFS:

  • We always follow one path as far as possible before backtracking.
  • We must remember which nodes are already seen, so we don’t get stuck in loops.
  • The edges we use when we first discover new nodes form a DFS tree.

Example DFS starting at KOL

Assume we always explore outgoing edges from a station in alphabetical order of station code: DEL, KAN, NAG, PUN, SEC (when applicable).

  1. Start at KOL. Mark KOL as visited.
  2. Neighbours of KOL: DEL, KAN, NAG.
    In alphabetical order: DEL first.
  3. Go to DEL, mark DEL visited.
  4. Neighbours of DEL: KAN.
    Go to KAN, mark KAN visited.
  5. Neighbours of KAN: none.
    DFS from KAN is done → backtrack to DEL.
  6. At DEL, there are no more unvisited neighbours → backtrack to KOL.
  7. At KOL, next neighbour is KAN, already visited → skip.
  8. Next neighbour: NAG. Go to NAG, mark NAG visited.
  9. From NAG, neighbour is SEC → visit SEC.
  10. From SEC, neighbour is PUN → visit PUN.
  11. From PUN, neighbour is DEL, but DEL is already visited → stop.
  12. Backtrack: PUN → SEC → NAG → KOL.

DFS visit order:
KOL → DEL → KAN → NAG → SEC → PUN

The edges that first discovered each new station form the DFS tree rooted at KOL.

3. Trains as Nodes & Stations as Edges – Mutual Recursion

In the previous section, stations were nodes and trains were edges.

But sometimes it is more natural to think of:

  • Nodes = trains (T1, T2, …, T9)
  • Edge between two trains if they share a station where you can transfer.

We can simplify and say:

Two trains are connected if they share at least one station among their start or end stations.

Example connections:

  • T1 and T2 share both KOL and NAG.
  • T1 and T3 share NAG.
  • T6 and T7 share KOL and DEL.
  • T6 and T8 share DEL.

If we start on some train, say T1, we might want to know:

“Which other trains are reachable if I keep changing trains whenever they share a station?”

To explore this “train graph”, it is convenient to write two recursive procedures:

  • visitTrain(trainId)
  • visitStation(stationCode)

They will call each other:

  • visitTrain marks a train as seen and then calls visitStation on all stations it touches.
  • visitStation looks at all trains that use that station and calls visitTrain on trains not seen yet.

This is called mutual recursion:

  • A calls B, B calls A, and so on.
  • We must still keep track of visited trains and visited stations so that the recursion eventually stops.

Pseudocode – mutual DFS for trains & stations

Data we keep:

* seenTrain: dictionary from train id → boolean (initially all false)
* seenStation: dictionary from station code → boolean (initially all false)
* For each train T, we know:
    * startStation[T]
    * endStation[T]

Procedure visitTrain(T)
1. If seenTrain[T] is true, return.
2. Set seenTrain[T] = true.
3. Let s = startStation[T], e = endStation[T].
4. Call visitStation(s).
5. Call visitStation(e).

Procedure visitStation(S)
1. If seenStation[S] is true, return.
2. Set seenStation[S] = true.
3. For each train U such that startStation[U] = S or endStation[U] = S:
    * Call visitTrain(U).

Quick question: Why two “seen” dictionaries?

Q: Why do we need both seenTrain and seenStation?

Answer:

  • To avoid calling visitTrain again on the same train.
  • To avoid calling visitStation again on the same station.
  • Without these dictionaries, visitTrain and visitStation could bounce between the same train and station forever.

4. Recursion as a General Idea

DFS procedures are recursive: they call themselves on smaller subproblems. Here we zoom in on recursion itself.

Our DFS procedures are recursive: they call themselves (directly or via mutual recursion) on smaller subproblems.

Recursion is based on inductive definitions:

  • A base case where we know the answer directly.
  • An inductive step where we solve a problem in terms of smaller versions of itself.

We will look at three classic examples:

  1. Factorial of a number.
  2. Sum of a list.
  3. Recursive insertion sort.

4.1 – Factorial

The factorial of a natural number n is:

  • n! = n × (n−1) × (n−2) × … × 2 × 1
  • 0! is defined to be 1.

One way to think of n!:

It is the number of different ways to arrange n students in a line.

Inductive definition:

  • Base case: 0! = 1
  • Inductive step: n! = n × (n−1)! for n > 0

We translate this into a recursive procedure:

procedure factorial(n):
    if n == 0:
        return 1
    else:
        return n * factorial(n - 1)

When we call factorial(3):

  • factorial(3) suspends until it knows factorial(2)
  • factorial(2) suspends until it knows factorial(1)
  • factorial(1) suspends until it knows factorial(0)
  • factorial(0) hits the base case and returns 1
  • Then the calls resume in reverse:
    • factorial(1) returns 1 × 1 = 1
    • factorial(2) returns 2 × 1 = 2
    • factorial(3) returns 3 × 2 = 6

The computer keeps a call stack of suspended calls until it reaches the base case.

🧠 Deep Dive: What is a Stack Frame?

When a function calls another function (or itself), the computer creates a Stack Frame in memory.

This frame stores:

  • The function's arguments (e.g., n=3).
  • Local variables.
  • The return address (where to go back to when finished).

These frames pile up like a stack of plates. The one on top is the active one. When it returns, it is popped off, and we resume the one below it.

Also note:

If we mistakenly call factorial(−1) with this definition:

  • factorial(−1) calls factorial(−2)
  • factorial(−2) calls factorial(−3)
  • … and so on, never reaching 0.

Without a base case that is actually reachable, the recursion never terminates.

    4.3 – Sum of a List (Recursive)

    For lists, the natural “nothing” value is the empty list.

    We define the sum of a list of numbers recursively:

    • Base case:
      If the list is empty, the sum is 0.
    • Inductive step:
      If the list is not empty, take the first element and add it to the sum of the rest of the list.

    Pseudocode:

    procedure listSum(L):
    if L is empty:
        return 0
    else:
        return first(L) + listSum(rest(L))

    Example on [1, 2, 3, 4]:

    • listSum([1,2,3,4]) = 1 + listSum([2,3,4])
    • listSum([2,3,4]) = 2 + listSum([3,4])
    • listSum([3,4]) = 3 + listSum([4])
    • listSum([4]) = 4 + listSum([])
    • listSum([]) = 0 (base case)
    • So total = 1 + 2 + 3 + 4 + 0 = 10.

      4.5 – Recursive Insertion Sort (Idea Only)

      We can also write insertion sort recursively.

      Idea:

      • Any list of length 0 or 1 is already sorted.
      • For a longer list:
        1. Take the first element x.
        2. Recursively sort the rest of the list.
        3. Insert x into the correct position in the sorted rest.

      Pseudocode (high level):

      procedure insertionSort(L):
    if length(L) ≤ 1:
        return L
    else:
        let x = first(L)
        let R = rest(L)
        let sortedR = insertionSort(R)
        return sortedInsert(x, sortedR)

      Here sortedInsert(x, sortedR) is the same helper we used before:

      • it walks through the sorted list sortedR
      • finds the correct place for x
      • returns a new sorted list.

      You do not need to run insertion sort on this page; this part is explanatory only.

      5. Generic DFS: Pseudocode on an Adjacency Matrix

      We move from train and mentoring stories to a generic DFS that works on any graph represented as an adjacency matrix.

      Now we move from specific stories (trains, mentoring) to a generic DFS algorithm on any graph.

      Goal:

      • Given a graph and a starting node i, find all vertices reachable from i using DFS.

      We will assume:

      • The graph has n vertices numbered 0..n−1.
      • We have an n × n adjacency matrix adj where:
        • adj[u][v] = 1 if there is an edge from u to v.
        • adj[u][v] = 0 otherwise.
      • We have a dictionary visited from vertex → boolean.

      Pseudocode: DFS on an adjacency matrix

      procedure DFS(i):
    visited[i] = true
    for each vertex j from 0 to n−1:
        if adj[i][j] == 1 and visited[j] == false:
            DFS(j)

procedure exploreFrom(start):
    for each vertex v from 0 to n−1:
        visited[v] = false
    DFS(start)

      After DFS(start):

      • Every vertex with visited[v] = true is reachable from start.
      • If all vertices are visited, the graph is connected (from that start node).

      Mini question: Why no infinite circles?

      Q: Why does DFS not get stuck going in circles on a graph with cycles?

      Answer:

      Because we keep a visited array.
      Every time we explore a vertex, we mark visited[v] = true and never call DFS on v again.
      So even if there is an edge back to a visited vertex, we skip it.

      6. Mentoring Graphs & Study Cycles

      We build a directed mentoring graph from marks, then use DFS-style exploration to find 3-step study cycles Maths → Physics → Chemistry.

      We have 8 students and their marks in Maths (M), Physics (P) and Chemistry (C).

      One student can mentor another in a subject if:

      • Their mark in that subject is between 10 and 20 marks higher, inclusive.

      For example, if A has 75 in Maths and B has 60 in Maths, A can mentor B in Maths.

      Student Maths Physics Chemistry
      A 69 75 76
      B 59 87 57
      C 82 53 50
      D 41 60 79
      E 64 75 85
      F 40 88 49
      G 68 77 78
      H 69 58 62

      Mentoring rule (directed edges):

      Student X mentors student Y in subject S if
      mark[X][S] – mark[Y][S] is between 10 and 20, inclusive.

      We are especially interested in 3-step study cycles of the form:

      Maths → Physics → Chemistry, and back to the start student.

      Concretely:

      A study cycle is a triple (X, Y, Z) such that:
      • X mentors Y in Maths
      • Y mentors Z in Physics
      • Z mentors X in Chemistry

      Example cycles

      Cycle 1: B → F → A → B

      • B mentors F in Maths (59 − 40 = 19)
      • F mentors A in Physics (88 − 75 = 13)
      • A mentors B in Chemistry (76 − 57 = 19)

      Cycle 2: C → A → H → C

      • C mentors A in Maths (82 − 69 = 13)
      • A mentors H in Physics (75 − 58 = 17)
      • H mentors C in Chemistry (62 − 50 = 12)

      6. Discovering Study Cycles with DFS

      We can think of each student as a node.
      For each subject (M, P, C), we draw a directed edge from mentor to mentee.

      We want to find all 3-step cycles of the form:

      • Maths edge, then Physics edge, then Chemistry edge, back to the start.

      Strategy:

      • Use DFS.
      • At each step, keep track of:
        • The current student.
        • The path length (0, 1, 2, 3).
        • The sequence of subjects used so far (e.g., "M", "MP", "MPC").
      • We never explore paths longer than 3 edges.
      • When we come back to the start student with subject sequence "MPC", we have found a valid study cycle.

      Pseudocode sketch (conceptual)

      procedure DFSStudy(startStudent):
    mark all students as not seen in this search
    call explore(startStudent, startStudent, "", 0)

procedure explore(start, current, subjectSeq, length):
    if length == 3:
        if current == start and subjectSeq == "MPC":
            record this cycle
        return

    if length == 0:
        nextSubject = "M"
    else if length == 1:
        nextSubject = "P"
    else:
        nextSubject = "C"

    for each student next such that current mentors next in nextSubject:
        explore(start, next, subjectSeq + nextSubject, length + 1)
